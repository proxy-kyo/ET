# 原住居民用服务端 AI 驱动，对客户端与真人玩家不可区分

世界观是玩家降临到原住居民的世界，玩家才是外来者。原住居民自己打怪、升级、交易，在任何玩家眼里都必须和真人完全看不出区别。

原住居民的 Unit 跑在地图纤程里，由 behaviortree 驱动，没有 Gate 连接，不走网络。不用机器人客户端：每个原住居民一条连接、一组纤程，开销按人数线性增长，而且 ET 现成的 `robot` 包依赖 `mapplay`，legend 用不了。

为了做到不可区分，有以下约束：

- 原住居民和玩家是同一种单位，有同样的等级、数值、背包、装备，都持久化在 MongoDB 里。
- 打怪、拾取、交易、聊天等动作，服务端只有一套入口。玩家的消息处理器和原住居民的 AI 调用同一个函数，所以两者的规则天然一致。
- 发给客户端的消息不得带任何能区分两者的信息，包括单位类型字段、ID 的生成方式或号段、名字规则、在线和离线状态，以及只有其中一方才会出现的消息。
- 服务端要判断「这个单位有没有客户端连接」时，看的是它有没有 `UnitGateInfoComponent`，不看 `UnitType`。

规模：原住居民的数量按单进程能承受的上限来定，不预先拍一个数。人口总预算（真人加原住居民）等于单进程的承载上限，原住居民的数量做成配置参数。具体数值等原住居民的 AI 和 AOI 广播都写出来之后，再用压测确定。为了给原住居民留出余量，AI 的 tick 频率和 AOI 广播从一开始就要按「单位数是真人几倍」来设计。
