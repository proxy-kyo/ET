# 命令行客户端：客户端动作单一入口，每个动作都有命令

legend 有两种客户端：Unity 客户端和命令行客户端。命令行客户端是一个单独的进程，没有画面，通过网络连接服务端。它有两个用途：一是不开 Unity 也能测试功能，二是压测。

客户端的每个动作（登录、移动，以及以后的攻击、拾取、交易、聊天）在客户端逻辑层只有一个函数。Unity 的 UI 和命令行命令都调用这个函数，UI 不直接发协议。这样命令行测到的就是真人走的那条路，压测的负载也和真人一致。这条规则和 ADR 0005 在服务端的「动作只有一套入口」对称。

新增客户端动作时，必须在同一次改动里加上它的命令和一个短别名。命令行的代码放在 legend 包内，不单独建包，这样动作和它的命令总是一起提交。

不用 ET 的 robot 包：它和服务端跑在同一进程，压测时客户端和服务端抢 CPU，而且它的登录流程依赖 mapplay。不复用 ET 控制台的「模式」：命令行客户端的命令都是一级命令，别名由它自己解析。
