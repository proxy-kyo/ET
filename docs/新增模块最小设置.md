# 新增 ET 模块的最小必要设置

本文只说明在本项目中新增一个独立模块（Package）必须完成的设置。

## 1. 创建模块目录

目录必须位于：

```text
Packages/cn.etetet.<模块名>/
```

建议的最小结构：

```text
Packages/cn.etetet.<模块名>/
├── package.json
├── packagegit.json
├── AGENTS.md
└── Scripts/
    ├── Model/
    │   └── Share/PackageType.cs
    └── Hotfix/
```

如果有客户端视图代码，再按实际需要增加：

```text
Scripts/ModelView/
Scripts/HotfixView/
```

不要为了“以后可能用到”提前创建其它目录。

## 2. 创建 `package.json `

路径：

```text
Packages/cn.etetet.<模块名>/package.json
```

至少要设置：

```json
{
  "name": "cn.etetet.<模块名>",
  "displayName": "ET.<模块名>",
  "version": "4.0.0",
  "unity": "2022.3",
  "category": "模块",
  "dependencies": {}
}
```

规则：

- `name` 必须与目录名一致。
- 只声明实际使用到的包依赖。
- 依赖必须满足单向依赖规则：高层模块依赖低层模块，低层模块不能反向依赖高层模块。
- 如果代码访问了其它包的类型，必须在 `dependencies` 中声明对应包。

## 3. 分配唯一包编号

路径：

```text
Packages/cn.etetet.<模块名>/packagegit.json
```

内容至少包含唯一的 `Id` 和包名，例如：

```json
{
  "Id": 201,
  "Name": "<模块名>"
}
```

`Id` 不能与项目中已有包重复。可以先搜索已有的 `packagegit.json`，再选择编号。

## 4. 定义 `PackageType`

路径：

```text
Packages/cn.etetet.<模块名>/Scripts/Model/Share/PackageType.cs
```

最小代码：

```csharp
namespace ET
{
    public static partial class PackageType
    {
        public const int <模块名> = 201;
    }
}
```

这里的值必须与 `packagegit.json` 中的 `Id` 一致。

## 5. 声明场景类型（只有模块需要独立 Fiber/Scene 时才需要）

如果模块只是被其它模块调用，可以不定义场景类型。

如果模块需要自己的 Fiber 入口，则增加：

```text
Packages/cn.etetet.<模块名>/Scripts/Model/Share/SceneType.cs
```

示例：

```csharp
namespace ET
{
    public static partial class SceneType
    {
        public const int <模块名> = PackageType.<模块名> * 1000 + 1;
    }
}
```

然后为该场景提供对应入口：

```csharp
[Invoke(SceneType.<模块名>)]
public class FiberInit_<模块名> : AInvokeHandler<FiberInit, ETTask>
{
    public override async ETTask Handle(FiberInit fiberInit)
    {
        await ETTask.CompletedTask;
    }
}
```

没有独立 Fiber 需求时，不要增加 `SceneType` 和空的 `FiberInit`。

## 6. 配置模块入口文件

### 6.1 普通模块：不需要独立启动入口

如果模块只是提供组件、消息或工具，供其它模块调用，直接放置实际代码即可：

```text
Scripts/Model/...
Scripts/Hotfix/...
```

由使用它的上层模块负责创建组件或调用方法。此时不要新增空的：

```text
Entry.cs
FiberInit_*.cs
EntryEvent*.cs
```

### 6.2 独立运行模块：需要一个 Fiber 入口

如果模块需要在 ET 启动时自动创建自己的场景/Fiber，至少需要：

```text
Scripts/Model/Share/PackageType.cs
Scripts/Model/Share/SceneType.cs
Scripts/Hotfix/Share/FiberInit_<模块名>.cs
```

`FiberInit_<模块名>.cs` 是实际入口，必须绑定场景类型：

```csharp
namespace ET
{
    [Invoke(SceneType.<模块名>)]
    public class FiberInit_<模块名> : AInvokeHandler<FiberInit, ETTask>
    {
        public override async ETTask Handle(FiberInit fiberInit)
        {
            Scene root = fiberInit.Fiber.Root;

            // 添加该 Fiber 必需的组件或发布初始化事件。
            await ETTask.CompletedTask;
        }
    }
}
```

实际启动链为：

```text
ET.Entry.Start()
  → SceneTypeSingleton 根据 SceneName 找到 SceneType.<模块名>
  → FiberManager.CreateMainFiber(...)
  → [Invoke(SceneType.<模块名>)] FiberInit_<模块名>.Handle()
```

`ET.Entry` 是项目公共入口，业务模块不要重复定义。

### 6.3 需要分段初始化时再增加 EntryEvent

只有初始化确实需要拆成公共、服务端、客户端等阶段时，才增加：

```text
Scripts/Model/Share/EntryEvent.cs
Scripts/Hotfix/Share/EntryEvent1_InitShare.cs
Scripts/Hotfix/Server/EntryEvent2_InitServer.cs
Scripts/HotfixView/Client/EntryEvent3_InitClient.cs
```

然后在 `FiberInit_<模块名>.Handle()` 中按顺序发布事件：

```csharp
await EventSystem.Instance.PublishAsync(
    root,
    new <模块名>EntryEvent1());
```

如果只有一个初始化动作，直接写进 `FiberInit_<模块名>.Handle()`，不要为了形式增加事件文件。

## 7. 按代码职责放置文件

最小分层规则：

| 内容 | 放置位置 |
| --- | --- |
| Entity、Component、消息、枚举、共享类型 | `Scripts/Model` |
| 服务端逻辑 | `Scripts/Hotfix/Server` |
| 客户端逻辑 | `Scripts/Hotfix/Client` |
| 客户端 UI/视图逻辑 | `Scripts/HotfixView/Client` |
| 客户端视图模型或生成绑定类型 | `Scripts/ModelView` |

一个类通常放一个 `.cs` 文件；不要把服务端和客户端代码混放。

## 8. 增加包规范文件

路径：

```text
Packages/cn.etetet.<模块名>/AGENTS.md
```

至少说明：

- 模块用途和边界。
- 依赖哪些包。
- 入口或启动方式。
- 禁止复制哪些已有资源或协议。
- 最小验证方式。

没有特殊规则时，也要保留文件并明确继承：

```text
继承 Packages/cn.etetet.harness/AGENTS.md 的全部规则。
```

## 9. 让 Unity 识别模块

完成目录和 `package.json` 后：

1. 返回 Unity，让 Package Manager 刷新包。
2. 通过 Unity 重新生成项目文件（不要手工修改 `.csproj`）。
3. 如果模块包含资源、场景或 Prefab，按项目既有资源流程导入并生成 `.meta`。

不要手工创建或修改 `.meta`、`.csproj`。

## 10. 最小验证

至少执行项目唯一编译入口：

```powershell
dotnet build ET.sln
```

然后根据模块类型做最小运行验证：

- 普通共享模块：确认依赖模块可以引用其类型。
- 服务端模块：启动对应服务，确认 Fiber/Handler 正常注册。
- 客户端模块：进入对应场景，确认初始化入口执行。
- 消息模块：确认协议生成文件、发送端和接收端使用的是同一版本。

## 最小检查清单

- [ ] 目录位于 `Packages/cn.etetet.<模块名>/`
- [ ] `package.json` 存在，名称和目录一致
- [ ] `packagegit.json` 存在，`Id` 全局唯一
- [ ] `PackageType.cs` 存在，编号与 `Id` 一致
- [ ] 依赖已写入 `package.json`，且没有反向依赖
- [ ] 有独立 Fiber 才增加 `SceneType` 和 `FiberInit`
- [ ] 独立运行模块已配置 `[Invoke(SceneType.<模块名>)]` 入口
- [ ] 未在业务模块中重复定义公共 `ET.Entry`
- [ ] 只有确实需要分阶段初始化时才增加 `EntryEvent*.cs`
- [ ] 已添加包内 `AGENTS.md`
- [ ] 未手工修改 `.meta` 或 `.csproj`
- [ ] 已执行 `dotnet build ET.sln`

## 一句话原则

新增模块最少只需要：`package.json`、`packagegit.json`、唯一 `PackageType`、正确的依赖声明，以及实际业务代码；只有确实需要独立场景、资源或客户端视图时，才继续增加对应设置。
