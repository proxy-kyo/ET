# ET10 框架架构说明

> 代号"昭君" · 面向 AI 编码时代的 Unity + .NET MMO 游戏框架
> 本文档用于系统了解项目整体架构、功能分布与代码组织方式。

---

## 一、项目概述

ET10 是一个**模块化、分布式、支持热更新的大型多人在线游戏(MMO)框架**,客户端与服务端共用同一套 C# 代码。它的特别之处在于:不仅是底层框架,还自带一整套**开箱即用的 MMO 玩法系统**(技能/Buff/数值/AI/同步),并内建**面向 AI 协作开发的基础设施**(Harness 技能、Unity 桥接、Analyzer 架构约束、自动化测试)。

| 维度 | 数据 |
|---|---|
| 引擎版本 | Unity 2022.3.62f3c1 (LTS) |
| 业务包数量 | 56 个 `cn.etetet.*` |
| C# 文件数 | ~4,358 个 |
| C# 代码行数 | ~507,000 行 |
| 主包启用 | 42 个包 |
| 序列化 | MemoryPack(二进制) |
| 数据库 | MongoDB |
| 热更新 | HybridCLR(C# 原生热更) |
| 资源管理 | YooAssets |
| 配置工具 | Luban(Excel → C#) |

## 二、整体架构图

ET10 采用"双端共享 + 分布式服务端"的整体架构。客户端通过路由接入,服务端是多进程(多 Fiber)分布式集群。

```
┌─────────────────────────────────────────────────────────────────────┐
│                          客户端 (Unity Runtime)                        │
│  ┌───────────────┐  ┌──────────────┐  ┌───────────────────────────┐  │
│  │  YIUI UI 框架  │  │  YooAssets   │  │      HybridCLR 热更新       │  │
│  │ (UI/红点/特效) │  │  (资源加载)   │  │      (C# 代码热重载)        │  │
│  └───────────────┘  └──────────────┘  └───────────────────────────┘  │
│  ┌─────────────────────────────────────────────────────────────────┐ │
│  │        Gameplay 客户端表现层 (Unit / Move / Spell / AOI 视野)      │ │
│  └─────────────────────────────────────────────────────────────────┘ │
└───────────────────────────────┬───────────────────────────────────────┘
                                 │  KCP / TCP / WebSocket
                                 ▼
┌─────────────────────────────────────────────────────────────────────┐
│                      Router 软路由 (连接分发 / 内外网隔离)              │
└───────────────────────────────┬───────────────────────────────────────┘
                                 ▼
┌─────────────────────────────────────────────────────────────────────┐
│                   服务端分布式集群 (多进程 · 多 Fiber)                  │
│                                                                       │
│   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────────────┐  │
│   │  Realm   │   │  Gate    │   │  Map     │   │  Location        │  │
│   │ (登录认证)│   │ (网关)    │   │ (地图玩法)│   │ (Actor 位置服务)  │  │
│   └──────────┘   └──────────┘   └────┬─────┘   └──────────────────┘  │
│                                      │                                │
│   ┌─────────────────────────────────┴──────────────────────────┐    │
│   │  AOI 视野 · Unit · Numeric · Spell · Move · Recast 寻路       │    │
│   │  Item/Equipment · Quest · BehaviorTree(AI) · StateSync 同步   │    │
│   └────────────────────────────────────────────────────────────┘    │
│                                                                       │
│   ┌──────────────┐   ┌─────────────────┐   ┌──────────────────────┐  │
│   │  DB(MongoDB) │   │ ServiceDiscovery │   │  Aspire(云原生编排)   │  │
│   └──────────────┘   └─────────────────┘   └──────────────────────┘  │
│                                                                       │
│   通信底座: NetInner 内网消息 · ActorLocation 寻址 · Transfer 实体迁移  │
└─────────────────────────────────────────────────────────────────────┘
```

**核心运行时模型**:

- **Entity 体系**:一切皆 Entity / Component,Entity 存数据,System 存逻辑(ECS 风格)。
- **Fiber 模型**:服务端每个 Scene/进程跑在独立 Fiber(纤程)上,单线程内异步,多 Fiber 间通过消息通信,规避多线程锁竞争。
- **ETTask 异步**:自研单线程协程,贯穿全部异步逻辑(非 .NET Task)。
- **Actor 模型**:实体跨进程通过 ActorLocation 寻址通信,支持实体在进程间迁移(Transfer)。

## 三、包依赖分层图

ET10 用 Analyzer 在编译期强制包依赖规则:**只能高层依赖低层,严禁反向与循环依赖**(A 依赖 B,则 B 永远不能访问 A)。跨包访问必须显式声明依赖。

```
┌──────────────────────────────────────────────────────────────────────┐
│ 第5层  业务入口 / 玩法编排                                               │
│   wow(游戏入口) · login(登录) · mapplay(地图玩法→map/spell/item/quest) │
│   btnode · robot(→console) · test(测试)                                │
├──────────────────────────────────────────────────────────────────────┤
│ 第4层  玩法聚合                                                         │
│   map(→aoi/unit/netinner/move/numeric) · aoi(→unit/numeric)           │
│   actorlocation(→netinner)                                             │
├──────────────────────────────────────────────────────────────────────┤
│ 第3层  玩法基础 / 通信                                                  │
│   numeric(→unit) · move(→unit) · nav2d(→unit) · item(→unit)           │
│   netinner(→startconfig) · router(→startconfig/http)                  │
├──────────────────────────────────────────────────────────────────────┤
│ 第2层  系统基础                                                         │
│   unit · behaviortree · http · startconfig · console · yooassets       │
│   yiuiframework 及 YIUI 全家桶(yiui/reddot/tips/effect/gm/3ddisplay…)  │
├──────────────────────────────────────────────────────────────────────┤
│ 第1层  框架基石                                                         │
│   core(核心框架) · proto(协议) · loader(加载器) · excel(配置)           │
└──────────────────────────────────────────────────────────────────────┘
            依赖方向:上层 ───────▶ 下层(永不反向)
```

> 说明:实际仓库当前包含 56 个包,上图列出分层规范中的代表性包。`memorypack` / `mathematics` / `sourcegenerator` 作为编译期/序列化基础设施,被广泛依赖。

## 五、代码组织维度(每个包的内部结构)

ET10 的代码有**两个正交维度**:横向按"包"(功能模块)划分,纵向按"程序集层 × 端"划分。每个业务包内部都是统一结构(以 `cn.etetet.spell` 为例):

```
cn.etetet.spell/
├── Scripts/
│   ├── Model/          # 数据层:Entity / Component 定义(不可热更或慢热更)
│   │   ├── Client/     #   仅客户端
│   │   ├── Server/     #   仅服务端
│   │   └── Share/      #   双端共享
│   ├── ModelView/      # 数据层的 View 部分(Unity 相关数据)
│   ├── Hotfix/         # 逻辑层:System / Handler(热更程序集,改这里可热重载)
│   │   ├── Client/
│   │   ├── Server/
│   │   ├── Share/
│   │   └── Test/       #   测试用例(ATestHandler)
│   ├── HotfixView/     # 逻辑层的 View 部分(Unity 表现逻辑)
│   └── Editor/         # 编辑器扩展
├── Luban/              # 该包的 Excel 配置表(__tables__/Defines/Datas)
├── CodeMode/           # Luban 导出生成的 C# 配置代码与数据
│   ├── Config/{Client,Server,ClientServer}
│   └── Model/
└── Proto/              # 该包的协议定义
```

**程序集分层(对应顶层 `ET.*.csproj`)**:

| 程序集 | 内容 | 是否热更 |
|---|---|---|
| `ET.Core` | 框架核心 | 否 |
| `ET.Model` / `ET.ModelView` | 各包 Model 层(数据/实体定义) | 否(结构稳定) |
| `ET.Hotfix` / `ET.HotfixView` | 各包 Hotfix 层(全部逻辑) | **是**(HybridCLR 热重载) |
| `ET.Config` | Luban 导出的配置代码 | — |
| `ET.Loader` / `ET.Init` | 加载器与启动入口 | 否 |
| `ET.*.Editor` | 各类编辑器工具 | 仅编辑器 |

> 关键认知:**逻辑全部写在 Hotfix 层**,Model 层只放数据。这是 ET 能做到 C# 代码热更新的根本原因 —— 重载 Hotfix 程序集即可替换逻辑,而数据结构(Model)保持不动。

**Client / Server / Share 三端划分**:同一个包内,`Share` 是双端共享代码,`Client`/`Server` 各自独有。编译时按目标端裁剪,实现"一套代码库、双端共用"。

## 六、AI 开发基础设施(ET10 的核心差异化)

ET10 区别于传统 ET 的最大特点:把"AI 协作开发规范"做成了基础设施。

```
┌─────────────────────────────────────────────────────────────┐
│  AGENTS.md (最小入口)                                         │
│      └─▶ cn.etetet.harness/AGENTS.md (主规范)                │
│              └─▶ skills/index.md (技能路由索引)               │
│                      ├── et-code   (Entity/System/包依赖)    │
│                      ├── et-async  (ETTask/await 安全)       │
│                      ├── et-build  (编译/Proto/起服务/发布)   │
│                      ├── et-luban  (配置导出)                │
│                      ├── et-excel  (Excel 读写)              │
│                      ├── et-git    (提交规范)                │
│                      ├── et-tdd / et-test-* (测试闭环)       │
│                      └── et-unitybridge (操作 Unity Editor)  │
└─────────────────────────────────────────────────────────────┘
```

- **Analyzer 架构约束**:async 安全、实体生命周期、包依赖、Actor 用法在**编译期强制**。AI(或人)写错会直接编译报错,报错信息即架构教学。
- **UnityBridge**:让 AI 能查询 Unity 心跳、操作 Editor、跑 PlayMode、截图、触发热重载。
- **Test 框架**:基于 `ATestHandler` 的自动化游戏测试,支持 TDD 闭环。

## 九、总结

ET10 是一个**完整度极高、可直接用于商业 MMO 的游戏框架**,三大支柱:

1. **工业级分布式服务端** —— 多进程 Fiber、Actor 模型、服务发现、实体迁移、云原生部署。
2. **"魔兽世界式"完整战斗系统** —— 技能/Buff/数值/天赋/AI/双同步方案,设计深度面向真实大型游戏。
3. **面向 AI 开发的基础设施** —— Harness 技能 + Analyzer 约束 + Unity 桥接 + 自动化测试,让 AI 能在严格架构边界内安全开发。
